## 处理流水线（6 步，每本书都必须走完）

> ⚠️ **标题层级统一是横切必做项**（2026-08-17 实战发现）：OCR 会把答案行/提示框/页眉/题干行误标成标题，
> 导致 Obsidian 大纲（Outline）层级错乱。每本书在**侦察、清洗、校验**三阶段都要过一遍（见第 1/2/5 步），
> 否则拆分稿的大纲就是乱的。

### 第 1 步：侦察

1. 确认 origin 的 .md 结构：正文起点行号、标题层级（`# 章` / `### 节` / `#### 子块`）、题区标记词
2. **扫描标题层级**：用 `_scan_headings.py` 检查章/节/小节层级是否统一、是否有跳级；用 `_dump_headings.py` 导出标题序列人工看是否存在答案行（`### 03. D`）、提示框（`## 注意`）、页眉残留（`## 考研数学基础30讲 · XX分册`）、题干行（`## 1 ）为什么要…`）被 OCR 误标为标题 —— 见《标题层级统一（专章）》
3. 统计 imgs 图片数、引用与文件是否一一对应
4. 扫描广告特征词、二维码、重复标题、缺失章节标题
5. 记录 `BODY_START`（正文起点行号）——校验脚本要用

### 第 2 步：清洗 origin（直接改 origin，禁止改拆分稿再合并）

- **删广告文字**：公众号 / 微信（含"一手+V"）/ QQ群 / 联系方式 / 价格（"4.9元包邮"）/ 页眉页脚 / "配套课程"类
- **删二维码广告图片**：见下方《二维码处理》专章
- **删重复标题**：OCR 常把同一标题打两遍（如 `# 第1章 xxx` 后紧跟 `# xxx`），只留一份
- **删目录/前言/版权页/页眉**：正文起点（BODY_START）之前的部分，保留需要的前言类内容时单独判断
- **修错字标题**：如"多元函数和分学"→"多元函数积分学"
- **修结构标题**：见《结构问题（专章）》——章标题 `## 第N章`、节标题脚注污染 `###  $^{*}N.M$`、重复章标题、习题区标题被污染成 `###`，**拆分前必须清完**
- **统一标题层级（必跑，2026-08-17 新增）**：见《标题层级统一（专章）》。目标层级：
  - 408：`# 第N章`=H1 / `## N.M 节`=H2 / `### N.M.K 小节`=H3 / `####`=H4；`### 考点追踪`=H3；`#### 题型`=H4；`#### N. 数字条目`=H4；`##### （N）括号条目`=H5；`### （一）考纲子项`=H3
  - 30讲数学：`## 第N讲`=H2 / `### 三件套`=H3 / `#### 内容节`=H4 / `##### 子项`=H5
  - 30讲数学题目（2026-08-17 新增，进大纲方便跳转）：精讲区 `例N.M …` → 父级+1（多为 H6，无子项处 H5/H4）；习题精练区 `#### 习题`/`#### 解答` 下的 `N.M …` 题号行 → H5。题号后允许跟空白或全角（；**标题只留纯编号（`例1.1`/`1.1`），题干挪回正文行**（题干太长不进标题）。脚本 `_add_ti_headings.py` + `_shorten_ti_headings.py`
  - 408课后习题（2026-08-18 新增，进大纲方便跳转）：`本节试题精选/本节习题精选` 与 `答案与解析` 区内，题型小节（一、单项/二、综合）下 `NN.` 题号行 → `##### NN` 纯编号标题，题干/答案/【解答】挪回正文行。脚本 `_add_ti_headings_408.py`（幂等）+ `_check_ti_continuity_408.py`（必跑）
  - 1000题：`# 篇`=H1 / `## 第N章`=H2 / `### 题型`=H3
  - 答案行、提示框、题干行、页眉残留 → 去 `#`/加粗/删除（脚本：`_norm_408_headings.py`、`_norm_math_headings.py`、`_norm_1000_headings.py` + 对应 `_pass2.py`）
  - **改完 origin 必须同步拆分脚本标题正则**（`_resplit_6books.py` 的 `SEC=^##`、`EX/ANS=^###`；`_split_1000.py` 的 `ZHANG/LING/TEST=^##`）
- **去公式边界空格**：`$ x $` → `$x$`（Obsidian MathJax 要求 `$` 与内容紧贴，否则不渲染）。只删**开 `$` 后、闭 `$` 前的空格**（配对法，不能一刀切——`x $y$` 的 `$` 前空格是文本分隔）；`$$ x $$` 同理；填空占位 `=$ ___` → `=\underline{\qquad}$`
- **不加快速跳转目录**（2026-08-17 起弃用）：原在 origin 最前加 `## 📑 快速跳转` + `[[#章名]]` 锚点，但 Obsidian 阅读视图点 H2 锚点跳转失效，且大纲（Outline）已能正常跳转，故**不再添加**；历史文件可用 `_remove_toc.py` 移除该块（对拆分零影响，拆分脚本 `find_body` 本就跳过它）
- **检查 `$` 成对**：每行 `count($) - 2*count($$)` 必须为偶数，奇数行 = OCR 丢/多 `$`，逐行人工修
- **补缺章标题**：内容在、标题丢 → 按前后文补 `# 第N章 章名`；内容真缺 → 记录清单报告用户，不擅自造内容
- 清洗后**不得引入新内容**，只删/改不增

### 第 3 步：写/复用拆分脚本

统一模式（参考 `_resplit_6books.py`，根目录）：

- 输入：origin 正文（BODY_START 起）+ 现状拆分稿的文件名/frontmatter（作为边界元数据）
- 规则：
  - 408：`# 第N章` → 章目录；`### x.y` → 考点文件；`#### x.y.k 本节(试题|习题)精选`/`答案与解析` → 习题文件；章内第一节前 → 导读
  - 数学：`## 第N讲` → 每讲一个文件
  - **1000题（分篇 → 分科）**：目录分三科（高等数学/线性代数/概率论与数理统计），每科章号重新计数
    - 结构：`1000题-试题册/{基础篇, 强化篇, 综合篇}/{高数, 线代, 概率}/…`
    - 基础篇/强化篇：先按篇分，篇内再按科目分（高数/线代/概率），文件名 `第N章 章名.md`
    - 基础篇高数下的"零基础"部分 → `基础篇/高数/零基础摸底.md`
    - 综合篇：`综合篇/测试卷一.md` ~ 测试卷四.md（不分科，直接放篇目录下）
    - 解析册同结构
- **图片引用**：一律改写为指向 origin 的相对路径（根据文件深度算 `../` 数量）
  - 拆分稿/<书>/<章>/导读.md → 3 级 `../../../origin/<书>/imgs/`
  - 拆分稿/<书>/<章>/考点|x.md → 4 级 `../../../../origin/<书>/imgs/`
  - 拆分稿/数学/<书>/xxx.md → 3 级
- 输出：frontmatter 沿用现状文件；正文 = origin 原文切片；**不生成脚本噪音行**

## 结构问题（专章）——拆分前必查（2026-08-16 实战沉淀）

> OCR 会把标题结构弄坏，导致拆分脚本静默丢整章/整节/整个习题区，校验字数/公式都测不出来。**这类问题必须在清洗 origin 阶段检查并修完。**

### 问题类型 → 后果 → 修复

| 类型 | 症状（实际例子） | 后果 | 修复 |
|---|---|---|---|
| 章标题降级 | `## 第5章`（双井号） | 拆分脚本只认 `# 第N章`，整章并入上一章 | `## 第N章` → `# 第N章 章名`，并删后面重复的章名行 |
| 节标题脚注污染 | `###  $^{*}7.1$ I/O 系统基本概念 $^{①}$` | 节号被 `$…$` 包住，SEC 正则匹配不到，整节并入上一节 | 去掉 `$…$`/脚注 → `### 7.1 I/O 系统基本概念` |
| 重复章标题 | `# 第7章` 出现两次（章节页+正文页） | 拆分时第二个覆盖第一个，**中间内容丢失** | 删第二个，保留第一个（或合并） |
| 习题区标题污染 | `###  $^{7}$1.3 本节习题精选`（应 `#### 7.1.3`） | 习题区并入考点文件，习题丢 | 改 `#### 7.1.3 本节习题精选` / `#### 7.1.4 答案与解析` |
| 子节标题污染 | `####  $^{*}7.1.1$ 输入/输出系统` | 不影响拆分边界，但结构脏 | 去掉 `$^{*}$` |
| 节名含 `/` | 节名 `I/O` → 文件名 `7.1-I/O …md` | `/` 被当路径分隔符，文件落错目录（`7.1-I/O` 变两层） | 拆分脚本加 `safe()` 清洗非法字符 |

## 公式边界与跨行块（专章）——校验盲区，2026-08-16 发现

> **关键盲区**：`_validate_dir.cjs` 只校验**单行** `$...$`，**跨行 `$$...$$` 块内的公式从没被 KaTeX 校验**。之前"FAIL=0"的结论有盲区，必须补跑 `_validate_blocks.cjs`。

### 问题类型（OCR 造成）→ 后果 → 修复

| 类型 | 症状（实际例子） | 后果 | 修复 |
|---|---|---|---|
| 孤立 `$`/`$$` | 行内公式末尾 `$` 被打成 `$$`、或 `$$` 单独成行 | 后续所有 `$`/`$$` 配对整体偏移，连锁产生"块吞正文" | 定位孤立点（`_scan_dollar_unmatched.py`），改回正确边界 |
| 块吞正文 | `$$` 块范围错，混入中文正文 + 行内公式 | 块公式渲染异常（显示多余 $ 或乱码） | 修孤立点后连锁消失；剩余需人工对照 |
| 块内嵌 `$` | `$$` 块内出现 `$x$` | KaTeX 报"块内嵌行内$"，MathJax 显示多余 $ | 判断假块（`$$`→`$`）或去块内 `$` |
| 选项乱码 | `\qua　`(=\quad)、`(D　`(=(D))、`nfty`(=\infty)、`rac{`(=\frac)、丢 (C) 标签 | 选项公式内容错/渲染错 | `_fix_options.py` |
| 未知命令 | `\a` `\c` `\p` `\lef` 等截断命令 | KaTeX 渲染失败 | 对照上下文还原为 `a`/`c`/`p`/`\left` |

### 检查命令（校验阶段必跑，8 本 origin 全跑）

```bash
node _validate_blocks.cjs <md>        # 跨行 $$ 块 KaTeX 校验（补盲区，最关键）
python _scan_dollar_balance2.py       # 公式边界解析（跳过 \$ 转义、块内 $ 不算边界）→ 应"边界完整"
python _scan_dollar_lines.py          # 逐行单 $ 配对（跳过代码块/$$/\$）→ 应无奇数行
python _scan_dollar_unmatched.py      # 定位孤立 $/$$（承受点，修完重跑）
python _scan_unknown_cmds.py          # 未知 LaTeX 命令（OCR 截断）
```

### 根因与修复方法（2026-08-17 实战，已验证可修）

> 之前以为"797 个块吞正文"无法批量，实际**根源只有两类，都可修**：

| 根源 | 症状 | 修复 |
|---|---|---|
| **行内嵌 `$$`** | 两个行内公式紧贴 `$...^{\mathrm{T}}$$...$`（`$` 和 `$` 相邻凑成 `$$`） | `$$` → `$ $`（拆开，中间空格） |
| **跨行 `$...$` 块** | 真块误用行内 `$...$`：`$ \left\{\begin{array}{l}...\end{array}\right. $`，且内部行有 `$0, \alpha...\\$` 干扰 | 块级化：`$...$` → `$$...$$`，内部行首尾 `$` 去掉 |

**效果**：解析册 797 个块（16 个行内嵌 `$$` 根源）→ **0**；高数 163 个 FAIL（4 个跨行块根源）→ **0**。修好根源后，后面的"块吞正文/未配对"连锁全部自动恢复。

python _show_inline_bb.py <md>   # 定位行内嵌 $$

## Obsidian 渲染问题（专章）——黄色高亮误判

> **现象**：正文里有些文字显示为**黄色**。
> **原因**：Obsidian 的 markdown 高亮语法是 `==文字==`。C 代码比较表达式 `a == b == c` 的中间 `==b==` 会被 Obsidian **误识别为高亮**，渲染成黄色背景。

**受影响的书**：数据结构（34 处）、操作系统（3 处）——只有含 C 代码的书；数学书无此问题。

**修复**：把正文里含 `==` 的代码片段用**反引号行内代码**包裹（`` `a == b == c` ``），Obsidian 当代码处理，不触发高亮。
```bash
python _fix_highlight.py <md...>   # 自动包裹不含中文的代码片段
# 含中文的多比较表达式（如 "栈空：S.top==-1；栈满：S.top==-2"）需人工按代码边界拆包
```

**检测**：`python _scan_highlight.py`（已跳过反引号行内代码和 `$公式$` 内的 `==`，避免误报）。

**注意**：`$...$` 公式内的 `==`（如 `$Q.front == Q.rear$`）由 MathJax 优先渲染，**不会**触发 markdown 高亮，无需修。

## 数学块闭合 $$ 尾随文字（专章）——大纲整片消失，2026-08-17 发现

> **现象**：Obsidian 文件大纲里一大片标题消失（高数 16/17/18 讲整片不见），文件里标题明明存在。
> **原因**：多行 `$$` 数学块的**闭合行 `$$` 后面跟了文字**（如 `\end{array}\right.$$ 按最高次写一般式`）。Obsidian 不认这种闭合 → 数学块不关闭 → 后续 `$$` 配对全部错位 → 标题被吞进数学块，大纲消失。 parity 类校验（`$$` 计数/行级奇偶）**全部查不出**，因为总数恰好配平。
> **定位法（实测有效）**：二分排除——把文件劈半 + 末尾加 `## 第99讲 测试标题`，看测试标题是否进大纲，逐步缩小到行。
> **修复**：尾随文字移到 `$$` 下一行（注释独立成段）。
> **排查命令**：
> ```python
> # 找「闭合 $$ 后还有非 LaTeX 文字」的行
> for i, l in enumerate(lines):
>     if "$$" in l:
>         tail = l.split("$$")[-1].strip()
>         if tail and not tail.startswith("\\"): print(i+1, l)
> ```
> 注意：`$$\left\{\begin{array}{l}`（开启行带 LaTeX 代码）和 `\end{array}\right.$$`（闭合在行尾）都是**正常**的，只有闭合 `$$` 后尾随正文文字才是问题。

## 标题紧贴 HTML 块（专章）——标题被吞进 HTML 块，2026-08-17 发现

> **现象**：Obsidian 文件大纲里某个标题消失（如高数第1讲「三 函数极限的概念与性质」），文件里标题明明存在。
> **原因**：标题行**直接跟在 HTML 行后面，中间没有空行**（`</div>`、单行 `<table …>…</table>` 等）。CommonMark 的 HTML 块（type 6）一直延伸到空行为止 → 标题被吞进 HTML 块，不进大纲。
> **判别**：标题前一行是**文本**无所谓（ATX 标题可以打断段落，正常显示）；前一行以 `<` 开头（HTML 标签）才是问题。
> **修复**：标题与 HTML 行之间插一个空行。
> **排查命令**（8 本 origin 全跑，已固化为 `_scan_glue_heading.py`）：
> ```python
> import re
> for i, s in enumerate(lines):
>     if s.strip().startswith("```"): in_code = not in_code; continue
>     if in_code: continue
>     if re.match(r"^#{1,6} ", s) and i > 0 and lines[i-1].strip().startswith("<"):
>         print(i+1, s)  # 标题紧贴 HTML 行,需插空行
> ```
> **已知案例**：高数 L1291「#### 三 函数极限的概念与性质」← `</div>`、L8245「##### 1 物理应用」← `</div>`；操作系统 L8037/L16009、计算机网络 L8408/L13817 ← 单行 `<table>`。共 6 处，全部插空行修复。

## 二维码处理（专章）

### 判定方法（三层确认，缺一不可）

1. **OpenCV 初筛**：`cv2.QRCodeDetector.detect()` 对每张图跑检测（中文路径用 `np.fromfile` + `cv2.imdecode` 读取）
2. **宽高比辅助**：检出后看宽高比，0.9–1.35 高度疑似二维码；异常比例（如 0.2–0.85）可能是知识结构图/公式图，**不能只按比例删**
3. **目检确认**：用 luma `image_understand` 逐张看，确认是二维码（含 Logo 二维码、模糊二维码）才删

### 删除动作

- 删 origin 中该图片文件（`origin/<书>/imgs/img_NN.jpg`）
- 删 origin .md 中对应 `<img>` 引用行（连同包裹它的 `<div style="text-align: center;">` 空壳）
- 删除后重跑拆分 → 校验自动确认引用无残留

### 已知教训（不要重犯）

- 宽高比启发式有例外：0.71、0.85 的图可能是真二维码；0.19–0.85 的图多数是知识图。**一切以目检为准**
- 校验脚本只比对"引用字符串"不查文件存在性——必须额外跑图片存在性检查（第 5 步表格）
- 二维码就是广告，用户要求"二维码我都不要"，全部删除

## HTML 表格转换（专章）2026-08-17 —— 含公式的表格

**问题**：扫描书里大量 `<table border=1>` 的 HTML 表格，Obsidian 对其中的 `$...$` 公式渲染不可靠；且 Markdown 表格里数学公式若含 `|`（如 `\frac{|A|}{\lambda}`），`|` 会被当成列分隔符，表格直接裂开。

**处理**：把「含公式的真多列表格」转成 Markdown 管道表格（`_convert_tables_all.py`）。
- 单列表格（注/证/结论的边框盒）**不转**——它们是盒子，不是数据表。
- `colspan/rowspan` 表格**跳过**——Markdown 无法表达合并单元格。
- 单元格内 `|X|`（绝对值/行列式）→ `\lvert X \rvert`（否则管道冲突）。
- 保留单元格内的 `<img>`（拆分脚本靠它改图片路径）；单元格内换行压成空格（否则拆断表格行）。
- 转换后校验每行列数一致；不一致则跳过。

**易错点**：
- **Obsidian/格式化插件会自动对齐表格**：把 `|A|` 拆成 `| A |` 并补多余空列 → 转换后务必检查每行列数一致、`$..$` 内无裸 `|`。
- `re.sub` 替换串里的 `\l` 会被当转义报错 → 用 `lambda m: r"..."` 返回字面量。
- 只转「含 `$` 的多列表格」；纯文本框、无公式表保持 HTML（它们渲染正常）。

**配套**：`_scan_html_tables.py`（扫描）、`_convert_tables_all.py`（转换，含 DRY_RUN）、`_check_bare_pipes.py`（校验 $ 内无裸 |）、`_inspect_tables.py`（抽查）。
